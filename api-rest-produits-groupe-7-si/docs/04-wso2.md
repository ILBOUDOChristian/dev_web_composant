# 4. Démarrage de WSO2

WSO2 Micro Integrator orchestre le transfert d'un produit entre les deux
schémas PostgreSQL.

## Fichiers essentiels

- [pom.xml](../wso2/pom.xml) : build Maven, CAR et pilote PostgreSQL.
- [deployment.toml](../wso2/deployment/deployment.toml) : datasource et
  variables runtime.
- [Dockerfile](../wso2/deployment/docker/Dockerfile) : image WSO2.
- [ProductTransferAPI.xml](../wso2/src/main/wso2mi/artifacts/apis/ProductTransferAPI.xml) :
  flux `DBLookup -> transformation -> DBReport`.

## Configuration du service

WSO2 reçoit ces variables au démarrage du conteneur :

```text
WSO2_DB_HOST=db
WSO2_DB_PORT=5432
WSO2_DB_NAME=products_db
WSO2_DB_USER=products_user
WSO2_DB_PASSWORD=<même valeur que POSTGRES_PASSWORD>
WSO2_KEYSTORE_PASSWORD=<mot-de-passe du keystore local>
```

La datasource `PRODUCTS_DB` est définie dans
[deployment.toml](../wso2/deployment/deployment.toml). Le pilote
`postgresql-42.7.4.jar` doit être présent dans `wso2/deployment/libs`.

## Fonctionnement

1. WSO2 reçoit `POST /products/transfer`.
2. `DBLookup` lit `source.products`.
3. Le nom du produit est normalisé.
4. `DBReport` insère ou met à jour `cible.products`.
5. WSO2 retourne une réponse XML.

## Réponses et erreurs

| Cas | Statut HTTP | Réponse |
|---|---|---|
| SKU trouvé et transféré | `200` | `<transferResult status="transferred" sku="..." name="..."/>` |
| SKU absent de `source.products` | `404` | `<transferResult status="not_found" sku="..."/>` |
| Erreur technique (base indisponible, erreur SQL) | `500` | `<transferResult status="error" message="..."/>` |

Le `faultSequence` de `ProductTransferAPI.xml` intercepte les exceptions du
médiateur (`DBLookup`, `DBReport`) et renvoie le statut `500` avec
`status="error"` au lieu d'une erreur Synapse brute.

Reconstruire l'artefact manuellement (optionnel) :

```powershell
cd wso2
mvn validate
mvn package -Pdocker
cd ..
```

Le profil `docker` génère le CAR, copie le pilote JDBC, prépare le contexte
Docker et construit l'image
`api-rest-produits-groupe-7-si-wso2:1.0.0`. Avant ce build, la variable
`WSO2_KEYSTORE_PASSWORD` doit être disponible dans l'environnement PowerShell.
Ne pas l'écrire dans un document ni dans une commande sauvegardée.

```powershell
$env:WSO2_KEYSTORE_PASSWORD = "<mot-de-passe-local>"
mvn package -Pdocker
```

Pour une installation neuve, la procédure recommandée est de laisser Docker
Compose construire WSO2 automatiquement avec le Dockerfile multi-étapes :

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml build wso2
```

Cette commande utilise Maven dans Docker et ne nécessite donc pas Java ni
Maven sur la machine hôte.

## Démarrage WSO2

PostgreSQL doit être sain. L'image WSO2 est construite automatiquement par
Compose :

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.dev.yml ps wso2
```

L'API est accessible sur `http://localhost:8291`.

## Dépannage WSO2

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs --tail=200 wso2
docker inspect api-rest-produits-groupe-7-si-wso2-1
```

- `image not found` : reconstruire l'image WSO2 avec le build Maven/Docker.
- erreur de pilote JDBC : vérifier le fichier dans `wso2/deployment/libs`.
- erreur de connexion : vérifier `WSO2_DB_HOST=db`, le port interne `5432` et
  que PostgreSQL est `healthy`.
- `404 not_found` : le SKU n'existe pas dans `source.products`.
- port `8291` occupé : changer `WSO2_HTTP_HOST_PORT` dans `.env`.
